# Logistic — проект сети поставок

## О проекте

Это учебная интерактивная модель транспортной задачи: нужно распределить паллеты между тремя складами и четырьмя магазинами так, чтобы полностью удовлетворить спрос магазинов и получить минимальную сумму транспортных тарифов.

Проект состоит из двух материалов:

- [Интерактивная демонстрация сети](outputs/network-design.html) — схема маршрутов, таблицы, настройки и пересчёт модели в браузере.
- [Подробный отчёт с расчётами](outputs/report.md) — балансировка, базовый и оптимальный планы, шаги MODI, проверка решения и анализ чувствительности.

Страница автономная: CSS и JavaScript уже включены в HTML. Не нужны установка зависимостей, сборка проекта или подключение к внешним сервисам.

## Исходные данные

| Объект | Значение |
|---|---:|
| Запас склада А | 120 паллет |
| Запас склада Б | 80 паллет |
| Запас склада В | 100 паллет |
| Спрос магазина М1 | 90 паллет |
| Спрос магазина М2 | 70 паллет |
| Спрос магазина М3 | 60 паллет |
| Спрос магазина М4 | 50 паллет |
| Вместимость одной фуры | 33 паллеты |

Общее предложение — 300 паллет, общий спрос — 270. Излишек в 30 паллет модель записывает на **фиктивный магазин** с нулевым тарифом. Это технический способ сбалансировать задачу: фиктивный поток не является доставкой и не создаёт рейсов.

Тарифы для каждой пары «склад → магазин» указаны в матрице на странице и в редакторе исходных данных. Цель — минимизировать сумму `объём маршрута × тариф за паллету`.

## Результат исходного примера

| Показатель | Значение |
|---|---:|
| Стоимость базового жадного плана | 2 290 у.е. |
| Стоимость оптимального плана | 2 130 у.е. |
| Экономия | 160 у.е. (6,99%) |
| Перевозится в магазины | 270 паллет |
| Рейсы по 33 паллеты | 11 |
| Средняя загрузка фуры | 74,38% |

Оптимальное распределение паллет:

| Склад / магазин | М1 | М2 | М3 | М4 | Фиктивный магазин | Всего со склада |
|---|---:|---:|---:|---:|---:|---:|
| А | 10 | 50 | 60 | 0 | 0 | 120 |
| Б | 80 | 0 | 0 | 0 | 0 | 80 |
| В | 0 | 20 | 0 | 50 | 30 | 100 |
| **Всего в магазин** | **90** | **70** | **60** | **50** | **30** | **300** |

Стоимость в этой модели учитывает только тарифы за паллеты. Стоимость рейса задана равной 0 у.е.; расходы на хранение излишка, временные окна, штрафы и ограничения пропускной способности не заданы. Поэтому результат демонстрирует оптимизацию по имеющимся данным и не является готовым коммерческим планом перевозок.

## Как устроен расчёт

1. Сайт складывает запасы и спрос. Если они не равны, он добавляет фиктивный магазин для излишка или фиктивный склад для дефицита. Фиктивные перемещения имеют нулевой тариф и исключаются из реальных рейсов.
2. Строится допустимое начальное распределение методом наименьшей стоимости. Для сравнения также рассчитан базовый жадный план: магазины обходятся по порядку, и каждый раз выбирается самый дешёвый склад с оставшимся запасом.
3. Оптимальный план улучшается методом потенциалов **MODI**. На каждом шаге сайт показывает маршрут для ввода, цикл перераспределения, объём переноса `θ` и новую стоимость. На исходных данных потребовалось три шага улучшения.
4. После улучшения выполняются проверки баланса, запасов, спроса и стоимости; независимая встроенная проверка min-cost-flow подтверждает результат MODI. На исходных данных оба способа дают 2 130 у.е. и одну и ту же матрицу перевозок.
5. Для активных реальных маршрутов сайт рассчитывает число рейсов как `округление вверх(паллеты / вместимость фуры)` и загрузку. Время доставки не рассчитывается, потому что длительности этапов не заданы.

## Как открыть и исследовать сайт

### Быстрый запуск

1. Скачайте репозиторий кнопкой **Code → Download ZIP** и распакуйте его либо клонируйте репозиторий.
2. Откройте файл `outputs/network-design.html` в браузере. Интернет и дополнительные программы не нужны.

Если браузер ограничивает работу локального файла, запустите локальный сервер из папки проекта:

```powershell
py -m http.server 8000
```

Откройте `http://localhost:8000/outputs/network-design.html`. Чтобы остановить сервер, вернитесь в окно PowerShell и нажмите `Ctrl+C`.

### Что нажимать на странице

1. В блоке **«Потоки по сети»** переключайте **«Оптимальный»** и **«Базовый»**, чтобы сравнить маршруты и стоимость. Толщина линии показывает объём перевозки; легенда объясняет цвет тарифа.
2. В **«Матрице перевозок»** смотрите паллеты по каждой паре склад–магазин. Тепловая заливка показывает объём потока.
3. В **«Методе потенциалов · MODI»** нажимайте **«Назад»**, **«Вперёд»** или **«Автоплей»**, чтобы проследить последовательные улучшения плана.
4. В **«Чувствительности тарифа и спроса»** выберите маршрут или магазин и передвиньте ползунок. Сайт пересчитает сценарий и сообщит, поменялся ли набор активных маршрутов.
5. В **«Своих данных»** измените запасы, спрос, тарифы или вместимость фуры и нажмите **«Пересчитать сеть»**. Нажмите **«Вернуть исходные данные»**, чтобы восстановить пример из проекта.
6. Кнопка **«Печать»** подготовит страницу к печати; кнопка **«Тема»** переключает оформление.
